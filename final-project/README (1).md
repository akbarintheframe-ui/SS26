# AquaWatch — Smart Water Quality Monitoring System

Real-time IoT monitoring system for tracking water quality across a dialysis-grade water treatment chain — from raw supply, through RO filtration, to point of use.

---

## Overview

AquaWatch monitors four critical water quality parameters — **pH, TDS (Total Dissolved Solids), turbidity, and temperature** — at three points in a water treatment pipeline:

| Node | Stage | Purpose |
|---|---|---|
| **Node 1** | Raw Water Inlet | Baseline contamination reading before treatment |
| **Node 2** | Post-RO Treatment | Validates RO filter effectiveness |
| **Node 3** | Point of Use | Final safety check before reaching the point of consumption |

Comparing readings across all three nodes — not just monitoring one point — makes it possible to localize *where* in the treatment process a water quality issue originates, rather than just flagging that something is wrong.

---

## Architecture

```
Sensors (pH / TDS / Turbidity / Temperature)
        ↓
    ESP32 (WiFi + MQTT publish)
        ↓
    HiveMQ Cloud (MQTT broker, TLS-secured)
        ↓
    Node-RED (subscribe, parse, route, visualize)
        ↓
    Live Dashboard (gauges + groups, one per node)
```

**Data flow in detail:**
1. Each node publishes a JSON payload to its own MQTT topic every publish cycle
2. HiveMQ Cloud receives and routes messages to all subscribers
3. Node-RED subscribes using a wildcard topic, parses incoming JSON, and routes each message to the correct node's dashboard group
4. Live gauges display pH, TDS, turbidity, and temperature per node, color-coded against AAMI water safety thresholds

---

## MQTT Topic Structure

```
aquawatch/node1/data     — Raw Water Inlet readings
aquawatch/node2/data     — Post-RO Treatment readings
aquawatch/node3/data     — Point of Use readings
```

Example payload:
```json
{
  "node": "node2",
  "node_name": "Post-RO Treatment",
  "ph": 7.09,
  "tds": 8.7,
  "turbidity": 0.65,
  "temperature": 25.9
}
```

Node-RED subscribes to all three at once using a single wildcard subscription:
```
aquawatch/+/data
```

## Current Status: Software-Simulated 3-Node Proof of Concept

The full data pipeline — MQTT topic structure, HiveMQ broker, and the Node-RED dashboard — is fully built and tested. Node 1, 2, and 3 data is currently generated by a **Node-RED simulation flow** (inject → function → mqtt out) that publishes realistic values to the exact same topic structure real ESP32 hardware will use.

This was a deliberate design choice: it allowed the entire cloud-to-dashboard pipeline — MQTT topics, broker configuration, and dashboard logic — to be developed and validated independently of physical hardware availability. Moving to physical sensors later requires no changes to the broker, topic structure, or dashboard, since HiveMQ and Node-RED have no way of knowing whether a message came from real hardware or the simulator.

## Alert Thresholds (AAMI Dialysis Water Standard)

| Parameter | Node 1 (Raw) | Node 2 (Post-RO) | Node 3 (Point of Use) |
|---|---|---|---|
| pH | 6.0 – 9.0 | 6.5 – 8.5 | 6.5 – 8.5 |
| TDS | < 500 ppm | < 10 ppm | < 10 ppm |
| Turbidity | < 5 NTU | < 1 NTU | < 0.5 NTU |
| Temperature | 5 – 35 °C | 15 – 30 °C | 20 – 28 °C |

---

## Tech Stack

- **Hardware:** ESP32 (WROOM-32), pH/TDS/turbidity sensors, DS18B20 temperature probe
- **Messaging:** MQTT protocol via HiveMQ Cloud (TLS-secured, port 8883)
- **Visualization:** Node-RED with node-red-dashboard
- **Data format:** JSON

---

## Setup

1. Import `/node-red/aquawatch-flow.json` into Node-RED (**☰ Menu → Import**)
2. Update the MQTT broker credentials in the `mqtt in` / `mqtt out` node configs to your own HiveMQ Cloud cluster
3. Deploy the flow
4. View the live dashboard at `http://localhost:1880/ui`
